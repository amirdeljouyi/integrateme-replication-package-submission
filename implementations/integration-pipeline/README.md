# Integration Pipeline

End-to-end pipeline for compiling tests, running coverage, filtering/reducing
LLM-generated tests, and comparing adopted vs generated tests.

## Layout

- `run_integration_pipeline.sh` - main entrypoint
- `run_pr_tests_pipeline.sh` - run the complete `pr-tests` filter/reduce/run/compare/annotation flow
- `src/cli/` - Typer CLI entrypoints
- `src/pipeline/` - pipeline orchestration + shared pipeline helpers
- `src/steps/` - step implementations (each step class lives in this module)
- `src/core/` - shared helpers/utilities
- `src/metrics/` - PMD/CPD + tri-compare tooling
- `libs/` - Java dependencies for test execution
- `jacoco-deps/` - JaCoCo agent jar
- `coverage-filter-1.0-SNAPSHOT.jar` - CoverageFilterApp tool
- `build/` - compiled test classes (generated by the pipeline)
- `tmp/` - working area (logs, coverage exec files)
- `pipeline-output/` - pipeline outputs (if used by your flow)

## Structure

Code organization and responsibilities:

- `src/pipeline/pipeline.py` - `Pipeline` class, target iteration, step dispatch
- `src/pipeline/config.py` - configuration, defaults, and config builder
- `src/pipeline/helpers.py` - pipeline-only helpers (paths, test discovery helpers)
- `src/steps/base.py` - `Step` abstract base class
- `src/steps/*.py` - concrete `{Name}Step` implementations colocated with their runtime helpers

## Quick start

From `implementations/integration-pipeline`:

```bash
./run_integration_pipeline.sh \
  ../_logs/tests_inventory.csv \
  ../../out/cut_to_fatjar_map.csv \
  all
```

CLI usage (direct):

```bash
python -m src [options...] <command>
```

Defaults:
- `tests_inventory.csv`: `../_logs/tests_inventory.csv`
- `cut_to_fatjar_map.csv`: `../out/cut_to_fatjar_map.csv`
- `generated_dir`: `../collected-tests/generated`
- `manual_dir`: `../collected-tests/manual`
- `repos_dir`: `../repos`

Examples:

```bash
python -m src clone
python -m src fatjar
python -m src generate-auto
python -m src sync --variants auto
python -m src coverage compare-reduced --top-n 5
python -m src reduce --variants adopted,agentic,pr-tests --max-tests 5
python -m src run --variants pr-tests
python -m src filter --variants all
```

Run the complete PR-tests pipeline:

```bash
./run_pr_tests_pipeline.sh
```

Optional environment overrides:

```bash
INCLUDES='com.alibaba.druid.pool.DruidDataSource' TOP_N=2 ./run_pr_tests_pipeline.sh
```

The reduction and annotation stages select at most the top 2 nonredundant,
positive-coverage tests per target and write them under
`pipeline-output/reduced/pr-tests/` and `pipeline-output/annotation/pr-tests/`. The PR-draft
stage then selects at most 2 tests per repository across those targets.
`TOP_N` may reduce both limits to 1. Targets whose adopted PR tests add no
coverage over the existing baseline are omitted. The final script report
validates the selected tests, annotations, and PR drafts.
For PR files containing the standardized `// Adopted Tests` comment, coverage is measured for
the test methods below that marker against a baseline containing the tests
above it. Without a marker, PR-only methods are inferred by comparing method
names with the collected manual test. Annotation reports target-class line
coverage separately from the test's overall line/method/branch/instruction
delta. A test can therefore show zero new target-class lines while adding
coverage in related classes; those related classes are listed in its annotation.
This marker-based path is used only while selecting candidate PR tests. It is
not the RQ4 before/after measurement.

RQ4 coverage is rerun from the committed Git states with `coverage
pr-snapshots`. The baseline is the recorded existing target-test file at the
PR merge base. The after phase runs that file plus the submitted test file at
the contributor's head when the PR adds or moves tests to another file. For
in-place modifications, the complete file is run at each revision. Both phases
use the repository's native Maven or Gradle route. JaCoCo coverage is extracted
for the CUT source file, including nested classes compiled from that file.

Run the focused PR-tests regression suite:

```bash
python -m unittest discover -s tests -v
```

Validate existing artifacts without rerunning the expensive Java stages:

```bash
VALIDATE_ONLY=1 ./run_pr_tests_pipeline.sh
```

## Steps

The CLI accepts a command argument (default: `all` in `run_integration_pipeline.sh`).
Some commands are grouped under subcommands: `llm`, `repair`, and `coverage`.

Priority order (recommended run sequence):

1) `clone`
2) `fatjar`
3) `generate-auto`
4) `sync --variants auto`
5) `compile`
6) `run`
7) `filter`  
8) `reduce`  
9) `llm all`  
10) `llm improve`  
11) `llm integrate`  
12) `llm integrate-sbs`  
13) `llm agent`  
14) `repair fix`  
15) `repair comment`  
16) `filter --variants adopted,agentic`  
17) `reduce --variants adopted,agentic --max-tests 5`  
18) `compare`  
19) `run --variants adopted,agentic`  
20) `pull-request-maker`  
21) `coverage compare`  
22) `coverage compare-reduced`
23) `coverage incremental`
24) `coverage incremental-target-cut`

Step descriptions:

- `clone` - clone repos for the configured selected CUT CSV and create/update `../repos` plus `../out/repo_roots.csv`. Command: `clone`.
- `fatjar` - build fat jars for the configured selected CUT CSV and write `cut_to_fatjar_map.csv` (default `../out/cut_to_fatjar_map.csv`). Command: `fatjar`.
- `generate-auto` - run `../run-agt/run-agt.sh` with the configured CUT-to-fatjar map, then run `../collect_tests.sh` so the generated tests land in `../collected-tests/generated` and refresh `../collected-tests/_logs/tests_inventory.csv`. By default it skips CUTs that already have generated tests; use `--no-skip-existing` to force reruns. Command: `generate-auto --skip-existing`.
- `sync` - run `../collect_tests.sh` against the existing `../run-agt/result` output in a staging directory, then refresh only `../collected-tests/generated` and inventory/logs. It intentionally does not modify `../collected-tests/manual`. When `../collected-tests/generated` already exists, rerun with `--force` to merge the staged output instead of replacing the tree. Right now only `--variants auto` is supported. Command: `sync --variants auto --force`.
- `compile` - compile generated and manual tests, resolve dependencies, retry safe source-level compile remediation for `auto`/`manual` test sources by adjusting exception declarations, and write `pipeline-output/compile/compile_summary.csv`. Command: `compile`.
- `run` - execute tests with JaCoCo and write `pipeline-output/coverage/coverage_summary.csv`, `pipeline-output/coverage/coverage_errors.csv` for failed/skipped/not-compiled runs, `pipeline-output/coverage/coverage_zero_hit.csv` for passed tests that did not hit the target class, and `pipeline-output/coverage/coverage_report_issues.csv` for passed tests where coverage extraction/reporting could not be mapped back to the target class (`--variants`); for `auto` and `manual`, it also retries safe compile remediation before recording the final outcome. Each execution attempt removes an existing JaCoCo destination first so coverage sessions from previous runs or CUT builds cannot accumulate. The runner accepts full generated, Top-100, improved, adopted, and agentic sources. Commands: `run --variants auto,manual`, `run --variants auto-100,improved --auto-100-dir pipeline-output/reduced`, and `run --variants adopted,agentic`.
- `filter` - run CoverageFilterApp to identify tests with coverage signal (uses fatjar + libs, `--variants`, `--skip-passed`, `--skip-passed-by-status`). Command: `filter --variants auto,manual` (auto) and `filter --variants adopted,agentic` (adopted).
- `reduce` - create reduced tests (top-N, `--max-tests`, `--variants`) based on coverage deltas. For Auto Top-100, ranking uses all current test-delta rows, removes stale or duplicate selectors, sorts coverage contribution descending, and removes unselected methods without reformatting selected test bodies. Smaller reductions continue to use only the kept/nonredundant delta rows. A suite with at most 100 tests is definitionally the full auto suite. It also writes per-target reduction summaries to `pipeline-output/reduced/<variant>/reduce_summary.csv`. Command: `reduce --variants auto --max-tests 100` (auto) and `reduce --variants adopted,agentic` (adopted). Outputs go under `pipeline-output/reduced/<variant>/`.
- `pr-tests` follows the adopted/agentic `run`, `filter`, `reduce`, coverage comparison, and annotation paths. Select it with `--variants pr-tests`.
- `llm all` - send reduced tests + manual tests (promptType `integration_all`) to produce adopted tests. Subcommand: `llm all`.
- `llm improve` - send reduced tests only (promptType `integration_improvement`) to produce `_Improved` tests. Subcommand: `llm improve`.
- `llm integrate` - send `_Improved` tests + manual tests (promptType `integration_merge`) to produce adopted tests. Subcommand: `llm integrate`.
- `llm integrate-sbs` - send `_Improved` tests + manual tests (promptType `integration_step_by_step`) to produce `_Adopted_StepByStep` tests. Subcommand: `llm integrate-sbs`.
- `llm agent` - use Codex CLI to integrate `_Improved` tests with manual tests and output adopted tests (defaults to CLI model). Before integration, the step adds a bounded selection of available repository guidance—including `README`, `CONTRIBUTING`, `AGENTS.md`, testing/development documents, and AI instruction files—to the prompt. The run log records each relative path, full-file SHA-256 hash, prompt length, and truncation status. For each run, the step also temporarily links the packaged `integrateme-pipeline` skill into the target repository, records its SHA-256 hash, and removes the link afterward. The skill lets Codex use this pipeline for target-scoped compilation or coverage when needed. The run is rejected if Codex changes tracked or non-ignored files in the target repository.
- `repair fix` - normalize adopted tests (via `src/steps/fix.py`) by removing `_scaffolding` imports/extends and adding `throws Exception` to test methods. Command: `repair fix`.
- `repair comment` - iteratively comment compile-error lines in `_Adopted` and `_Adopted_Agentic` tests until they compile. Command: `repair comment`.
- `compare` - compare adopted vs generated tests (PMD/CPD + tri-compare metrics).
- `coverage compare` - compare coverage for manual/auto/adopted/agentic tests; writes `pipeline-output/coverage/coverage_compare.csv`. Command: `coverage compare`.
- `coverage compare-reduced` - compare coverage for reduced auto/adopted/agentic tests using a shared top-N (`--top-n`, default 5); writes `pipeline-output/coverage/coverage_compare_reduced.csv`. Command: `coverage compare-reduced --top-n 5`.
- `coverage incremental` - compare covfilter class-level added coverage deltas (`class_deltas.csv`) for auto/adopted/agentic variants; writes `pipeline-output/coverage/coverage_incremental.csv`, including added line/branch percentages for target-class rows when coverage totals are available. By default it reports target-class rows only; use `--all-classes` to include every class row, and `--filtered-dataset` to select targets from `pipeline-output/annotation/dataset_filtered.csv`. Command: `coverage incremental`.
- `coverage incremental-target-cut` - subtract the existing-manual baseline from each matrix variant while requiring the exact outer target CUT. Identical JaCoCo class IDs produce exact line and branch deltas; separately compiled classes are accepted for lines only when their executable-line universes are identical. Every JaCoCo merge starts from a clean destination. Auto-100 reuses the full-auto execution for suites with at most 100 tests and requires a verified 100-method subset for larger suites. The output records the actual per-variant source count in `number_of_tests`, plus `measurement_basis` and `comparison_cohort_status`; historical improved/adopted/agentic outputs are explicitly marked as having unverified input lineage. Unverifiable rows remain unavailable instead of becoming zeroes. Command: `coverage incremental-target-cut --matrix pipeline-output/coverage/coverage_filtered32_all_variants.csv`.
- `coverage pr-snapshots` - compare the complete pre-PR target tests at the true merge base with the tests committed at the submitted head, using matching repository revisions and source-file-level CUT coverage. This command never uses the `// Adopted Tests` marker. Command: `coverage pr-snapshots --manifest ../../experiments/rq4/pr_snapshot_manifest.csv`.
- `pull-request-maker` - generate per-CUT PR drafts in `pipeline-output/pr/` from `resources/PR_TEMPLATE.md`.
- PR-test drafts select at most two methods per repository from below `// Adopted Tests`, ranked across that repository by measured coverage delta, and write concise tailored descriptions to `pipeline-output/pr/*.pr-tests.md`.
- `all` - run all steps in the priority order above.

## Inputs

- `tests_inventory.csv` (from collected tests)
- `cut_to_fatjar_map.csv` (from fatjar build)
- `libs/*` for JUnit and runtime deps
- `coverage-filter-1.0-SNAPSHOT.jar`
- `jacoco-deps/org.jacoco.agent-run-0.8.14.jar`
- adopted tests output root (`--adopted-dir`, default `pipeline-output/llm-out`)
- pull-request tests root (`--pr-tests-dir`, default `pipeline-output/pr-tests`); flat `Txx-*.java` files use `pipeline-output/annotation/target_rater_audit.csv` for target mapping, with class-name matching as fallback
- Codex CLI must be installed and logged in for `llm agent` step
- Agent prompt guardrails: `--agent-max-prompt-chars` (default 60000)

## Outputs

- `build/` compiled test classes
- `tmp/` logs, coverage exec files, and summaries
  - `pipeline-output/compile/compile_summary.csv`
  - `pipeline-output/coverage/coverage_summary.csv`
  - `pipeline-output/coverage/adopted_coverage_summary.csv`
  - `pipeline-output/coverage/coverage_errors.csv`
- `pipeline-output/` intermediate artifacts (covfilter/reduced/compare)
  - `pipeline-output/covfilter/` (covfilter outputs under `auto/`, `auto-original/`, `adopted/`, `agentic/`)
- `pipeline-output/reduced/auto/` (reduced generated tests)
- `pipeline-output/reduced/adopted/` (reduced adopted tests)
- `pipeline-output/reduced/agentic/` (reduced agentic tests)
  - `pipeline-output/reduced/auto/reduce_summary.csv`
  - `pipeline-output/reduced/adopted/reduce_summary.csv`
  - `pipeline-output/reduced/agentic/reduce_summary.csv`
  - `pipeline-output/compare/` (comparison CSVs)
    - `pipeline-output/compare/compare.csv`
    - `pipeline-output/compare/tri_compare.csv`
  - `pipeline-output/coverage/coverage_compare.csv`
  - `pipeline-output/coverage/coverage_compare_reduced.csv`
  - `pipeline-output/coverage/coverage_incremental.csv`

## Notes

- The launcher uses `python -m src` and assumes
  module sources are in `src/`.
- Coverage summary CSVs are tracked in git; everything else under `tmp/`
  is ignored by default.

## Prompt and template assets

Files under `resources/` are read by the pipeline at run time and sent to a model
or written into output. They are inputs, not documentation - editing them
changes results:

- `resources/AGENTIC_INTEGRATION_RULES.md` - the rule set the `agent` step sends to
  the model when merging generated tests into an existing suite. Formerly named
  `AGENTS.md`, which collided with the convention for coding-agent
  instructions. Override for an experiment with `ITL_AGENT_RULES=/path/to.md`.
- `resources/skills/integrateme-pipeline/` - a runtime/distribution skill describing how an
  agent can invoke the pipeline for focused compilation, JaCoCo collection, coverage
  filtering, and diagnosis. It is not a development skill. The `llm agent` step exposes
  it through a temporary `.agents/skills/integrateme-pipeline` link in the target
  repository, grants the Codex sandbox write access only to `pipeline-output/` and
  `workspace/`, records the skill bundle hash, and removes the link after the run.
- `resources/PR_TEMPLATE.md` and `resources/PR_DESCRIPTIONS.csv` - filled in by the
  `pull-request-maker` step.
